# Business & Product Prompts

## 1. Product Requirements Document

```
Create a Product Requirements Document for:

**Product:** [NAME]
**Problem Statement:** [THE PROBLEM]
**Target Users:** [PERSONAS]
**Business Goal:** [OBJECTIVE]

Include:
1. Executive Summary
2. Problem Statement
3. User Personas
4. Functional Requirements
5. Non-Functional Requirements
6. Success Metrics (KPIs)
7. User Stories
8. Timeline and Milestones
9. Risks and Mitigation
10. Out of Scope

Format: Clear, actionable, suitable for engineering team.
```

---

## 2. Technical Specification

```
Write a technical specification for:

**Feature:** [NAME]
**Context:** [EXISTING SYSTEM]
**Requirements:** [FROM PRD]

Include:
1. Overview and Goals
2. Architecture Design
3. Data Model Changes
4. API Changes
5. Security Considerations
6. Performance Impact
7. Testing Strategy
8. Deployment Plan
9. Rollback Plan
10. Monitoring Requirements
```

---

## 3. API Documentation

```
Create API documentation for:

**Endpoints:**
[LIST ENDPOINTS]

**Authentication:** [METHOD]

Include for each endpoint:
- HTTP method and path
- Description
- Request parameters (path, query, body)
- Request example
- Response schema
- Response examples (success and error)
- Status codes
- Rate limits
- Required permissions

Format: OpenAPI 3.0 spec + markdown summary.
```

---

## 4. Incident Post-Mortem

```
Write an incident post-mortem:

**Incident:** [BRIEF DESCRIPTION]
**Date/Time:** [TIMESTAMP]
**Duration:** [TIME]
**Impact:** [AFFECTED USERS/SYSTEMS]

Sections:
1. Executive Summary
2. Timeline of Events
3. Root Cause Analysis
4. Impact Assessment
5. Resolution
6. Action Items (with owners and deadlines)
7. Lessons Learned
8. Appendix (logs, metrics screenshots)

Be blameless and focus on systemic improvements.
```

---

## 5. Competitive Analysis

```
Analyze competitors for:

**Product/Feature:** [DESCRIPTION]
**Market:** [SEGMENT]

Analyze:
1. Top 3-5 competitors
2. For each competitor:
   - Core features
   - Pricing model
   - Strengths
   - Weaknesses
   - Market position
3. Feature comparison matrix
4. Pricing comparison
5. Market gaps
6. Differentiation opportunities
7. Recommended strategy

Format findings in a structured table format.
```

## 6. User Story Breakdown

```
Break down this feature into user stories:

**Feature:** [DESCRIPTION]
**Context:** [PRODUCT CONTEXT]

Create:
1. Epic-level story
2. User stories with acceptance criteria
3. Technical tasks for each story
4. Dependencies between stories
5. Story points estimates (Fibonacci)
6. Risk assessment for each story
7. Definition of Done

Format: "As a [persona], I want [action] so that [benefit]"
```

## 7. Launch Checklist

```
Create a launch checklist for:

**Product/Feature:** [NAME]
**Type:** [NEW PRODUCT / FEATURE / MAJOR UPDATE]

Categories:
1. Pre-Launch (1-2 weeks before)
   - Technical readiness
   - Documentation
   - Training
2. Launch Day
   - Deployment steps
   - Monitoring
   - Communication
3. Post-Launch
   - Monitoring (first 24-48 hours)
   - Rollback criteria
   - Follow-up actions

Include specific owners for each item.
```

## 8. Cost Analysis

```
Perform cost analysis for:

**Product/Feature:** [DESCRIPTION]
**Scale:** [EXPECTED USAGE]

Analyze:
1. Infrastructure costs
   - Compute
   - Storage
   - Network
   - Third-party services
2. Development costs
   - Initial build
   - Ongoing maintenance
3. Operational costs
   - Support
   - Monitoring
4. Cost per user/request
5. Break-even analysis
6. Optimization recommendations

Provide monthly and annual projections.
```

```
Draft a stakeholder communication for:

**Topic:** [SUBJECT]

**Purpose:** [INFORM / PERSUADE / UPDATE]

2. Background context
3. Current situation
4. Options/recommendations

Tone: [FORMAL / CASUAL / TECHNICAL]

```

## 10. OKR Definition

```
Define OKRs for:

**Team/Product:** [NAME]
**Timeframe:** [QUARTER]
**Context:** [BUSINESS PRIORITIES]

Create:
1. 3-5 Objectives (inspirational, qualitative)
2. For each objective, 3-5 Key Results:
   - Specific and measurable
   - Achievable but ambitious
   - Time-bound
3. Initiatives to achieve each KR
4. Tracking mechanism
5. Check-in cadence

Format:
Objective: [STATEMENT]
Key Result 1: [METRIC] from [CURRENT] to [TARGET]
Key Result 2: ...
```
